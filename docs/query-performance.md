# 大范围查询与按需明细

当前任务状态与优先顺序统一维护在[项目状态](project-status.md)；本文保留查询、导出边界和测量证据。

精确时间模式使用 `/api/time/summary`，由数据库按完整时间范围聚合，再返回日、项目和小时统计。当前周期与对比周期分别计算，边界之外和两个周期之间的记录不会混入结果。来源、设备和模型维度保留在聚合结果中，页面筛选和聚焦无需重新下载事件。

打开精确模式的来源、模型或项目详情时，页面才请求 `/api/time` 的一页事件，每页 50 条，按时间升序。下一页使用游标，上一页保存游标而非整页数据。关闭详情、切换筛选或刷新后会取消旧请求并重置分页。列表中的统计和排序始终基于完整范围的聚合数据，不会随事件翻页改变。

`/api/time` 支持重复的 `source`、`device`、`model` 和 `project` 查询参数。游标绑定时间范围和筛选条件；修改条件后必须从第一页开始。MySQL 使用区分大小写的事件、模型和项目身份比较，避免大小写不同的项目被合并。

费用直接汇总已存金额。缓存节省估算沿用现有非阶梯定价，并在每个事件上先将负值截为零，再求和；不能对日汇总只截一次，否则缓存写入较多的事件会抵消其他事件的节省。项目汇总同时保留完整的 reasoning token 数。

普通日汇总与精确明细导出使用 `/api/export.csv`，服务端在同一只读快照内每批读取 1,000 行并写入临时 CSV，释放数据库事务后再流式下载。浏览器直接管理下载，页面不积累全部明细。下载进度、失败和取消在浏览器下载列表查看；准备期间取消后停止后续分页并清理临时文件。趋势导出仍是当前图表的小型内存导出。

## 普通日期模式与复盘

页面启动先读取受相同鉴权保护的 `/api/config`，筛选、明细时间、额度绝对时间和复盘周期统一使用服务端 `DISPLAY_TZ`。无配置时沿用服务端主机时区；客户端不自行采用浏览器时区。日期型输入保持日历日期，精确输入在展示时区转换成 UTC 后供统计、对比和 CSV 共用。夏令时不存在的时段拒绝查询，重复小时使用较早的时刻；直接 API 请求可用显式 UTC 偏移选择另一个时刻。已有日汇总不会因展示时区改变而重建，采集端与中心仍应配置一致的时区。

普通看板通过 `/api/data?startDate=...&endDate=...` 读取所选日期；开启对比时，查询范围同时覆盖等长的上一周期。复盘页按当前周期和它的对比周期请求数据，例如本月同时包含上月，上月同时包含上上月。只有选择“全部”才加载全部历史日汇总和项目汇总。设备、来源、模型筛选仍在已取回的日期范围内完成，切换这些维度不额外请求。

日接口新增全局 `dateRange`、`dimensions` 元数据，保留全局 `eventRange`；它们不随请求日期缩小。因此选中没有数据的日期后，仍可选择其他历史设备、模型或全部历史。原有不带参数的接口保持兼容。

热力图只请求所选日期最后 28 天的 `/api/hourly?startDate=...&endDate=...`，与页面实际显示范围一致。服务端先用宽于任何时区偏移的 UTC 范围限定索引扫描，再按 `DISPLAY_TZ` 的本地日期过滤、聚合。不能直接使用已存 `usage_date` 替代展示时区，否则跨午夜和时区配置变化的旧记录可能漏掉。MySQL 的筛选维度保留大小写区别。

服务端小时查询共享进行中的请求，并缓存最多 4 个结果、每个最多 5,000 行、有效期 10 秒。缓存键包含时区、日期范围和数据库来源修订号，因此其他升级后的采集/同步进程提交变化后会立即失效；绕过项目写入入口的手工 SQL 只能靠到期刷新。额度查询也共享进行中的请求，成功结果缓存 60 秒、上游错误缓存 10 秒；凭据和响应不持久化到缓存文件。

2026-10-03，在含 83,419 条事件的独立 SQLite 副本上请求 2026-09-02 至 2026-09-29 的小时统计，首次 208 ms，随后三次为 2/1/1 ms；381 行、70,098 字节响应逐字一致。计时包含 HTTP 与 JSON 读取，不含浏览器绘图；隔离服务没有定价快照，这不是数据库扫描本身提速或所有环境的性能保证。

## 页面资源与浏览器回归

首页与复盘分别按路由加载，图表仍按可见区域加载。静态服务支持 gzip、ETag 条件请求和 HEAD；带构建哈希的资源使用私有长期缓存，HTML 每次重新验证。所有缓存判断之前仍执行访问认证。部署时需同步发布 HTML 和构建资源，页面资源失败会显示重新加载入口。

`npm run test:browser` 使用 Playwright Chromium、固定时钟、UTC 浏览器和 Asia/Shanghai 临时服务端，验证时区边界、配置失败重试、迟到请求、精确统计、明细分页与重试、CSV、移动布局、复盘和图表恢复。首次运行先执行 `npx playwright install chromium`（Linux 可加 `--with-deps`）；测试不使用个人日志或额度凭据。CI 在独立 Ubuntu job 执行。

每个页面、每类查询分别有 30 秒内存缓存，最多 4 个范围，每个结果最多缓存 5,000 条数组记录；大范围仍可查询，只是不进入缓存。缓存不持久化、不跨页面共享；刷新或本机采集完成会清空看板缓存。外部设备同步的变化可通过刷新获得，切换范围时也会重新读取已过期缓存，不新增后台轮询。切换日期时取消旧请求；迟到响应、失败或取消的请求不写入缓存。新范围未加载完或失败时显示加载/重试状态，不把上一范围的数据作为新范围展示或导出。

### 日查询本机对比

2026-09-26，同一份 SQLite 副本包含 927 条日汇总、1,442 条项目日汇总和 2,160 个小时分组。交替执行全历史接口与带日期接口各 3 次，耗时取中位数，包含 HTTP 响应读取与 JSON 解析，不包含浏览器绘图。使用同一服务、未启用压缩或客户端缓存；隔离服务未加载定价快照，费用来自已存金额，耗时不包含真实定价匹配的额外成本。

## 大范围查询的可重复基准

`npm run benchmark:query -- 100000`（或 `1000000`）只创建合成 SQLite：365 天、2 个设备、2 个来源、3 个模型、4 个项目。每个场景用三个新 Node 进程，避免建库内存计入查询峰值；操作系统文件缓存未清空，因此不是冷盘基准。脚本检查日/项目汇总 Token、金额及选定范围与生成数据一致，并在结束后删除临时数据库。

2026-10-04，macOS arm64、Node 22.22.2；时间取三次中位数，峰值 RSS 取三次最大值。计时含 `queryDaily`、全局元数据及 JSON 序列化，不含 HTTP、浏览器绘图、小时统计或真实价格匹配；合成模型没有价格，金额来自已存值。新进程查询前 RSS 约 49 MiB。

| 事件数 / 范围 | 日 / 项目日汇总行 | 响应字节 | 查询及序列化 | 进程峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 10 万 / 全部 | 4,380 / 17,520 | 10,664,883 | 159 ms | 157 MiB |
| 10 万 / 30 天 | 360 / 1,440 | 876,853 | 19 ms | 63 MiB |
| 100 万 / 全部 | 4,380 / 17,520 | 10,755,643 | 1,090 ms | 158 MiB |
| 100 万 / 30 天 | 360 / 1,440 | 884,213 | 190 ms | 63 MiB |

这个固定维度样本中，事件数增加十倍主要增加数据库扫描/分组时间；响应大小和查询内存没有同步增加，但全量响应已经约 10 MiB。仅加物化汇总不能减少返回的日/项目维度，也不能解决浏览器载入全部历史的成本。因此本轮保留现有日期查询与分页，不新增汇总表。若实际实例频繁查询百万级全历史，下一步应同时测量浏览器内存、服务并发和远程数据库，再决定服务端维度筛选/聚合与物化汇总；此处不宣称 QUERY-02 已完成预聚合。

## CSV 导出边界

- 导出遵循当前日期/时间、来源（包括聚焦来源）、设备和模型筛选，不包含上一周期对比数据；费用直接取已有记录，不重新估价。
- 日汇总与事件使用稳定复合键分页，支持超过单页的数据；字段含逗号、双引号或换行时进行 CSV 转义，可能被电子表格解释为公式的文本加单引号前缀。
- 复用看板鉴权，服务端返回附件并禁用缓存。完成准备后才发送响应头和准确的 Content-Length；准备失败不会伪装成成功下载，传输失败会断开下载。
- SQLite 在独立只读连接中建立快照；PostgreSQL 使用只读可重复读事务；MySQL 显式指定可重复读和一致性快照，遵循[官方事务契约](https://dev.mysql.com/doc/refman/8.4/en/commit.html)。并发插入、更新、删除或改写分页键不改变本次快照中的结果。
- CSV 在操作系统临时目录中以随机私有目录和文件生成（POSIX 目录 0700、文件 0600）。每次仅持有一页数据；需要约等于 CSV 大小的临时磁盘空间，并增加下载开始前的准备时间。下载开始前释放数据库事务，慢客户端只占用文件流。
- 正常完成、取消和失败均关闭句柄并删除临时目录；取消在当前数据库查询或文件写入返回后生效。进程被强制终止时无法执行 finally，遗留私有文件需由系统临时目录清理策略处理。本轮不添加跨进程清理器。
- 首页已移除历史汇总口径提示横幅；费用和项目归属说明仍保留在帮助文档，数据核对字段及历史费用保留策略未改变。

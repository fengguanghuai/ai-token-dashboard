# 大范围查询与按需明细

精确时间模式使用 `/api/time/summary`，由数据库按完整时间范围聚合，再返回日、项目和小时统计。当前周期与对比周期分别计算，边界之外和两个周期之间的记录不会混入结果。来源、设备和模型维度保留在聚合结果中，页面筛选和聚焦无需重新下载事件。

打开精确模式的来源、模型或项目详情时，页面才请求 `/api/time` 的一页事件，每页 50 条，按时间升序。下一页使用游标，上一页保存游标而非整页数据。关闭详情、切换筛选或刷新后会取消旧请求并重置分页。列表中的统计和排序始终基于完整范围的聚合数据，不会随事件翻页改变。

`/api/time` 支持重复的 `source`、`device`、`model` 和 `project` 查询参数。游标绑定时间范围和筛选条件；修改条件后必须从第一页开始。MySQL 使用区分大小写的事件、模型和项目身份比较，避免大小写不同的项目被合并。

费用直接汇总已存金额。缓存节省估算沿用现有非阶梯定价，并在每个事件上先将负值截为零，再求和；不能对日汇总只截一次，否则缓存写入较多的事件会抵消其他事件的节省。项目汇总同时保留完整的 reasoning token 数。

导出精确明细时才显式遍历完整范围的事件页，并显示进度状态，支持取消和错误后重试。导出仍需要在浏览器内存中构建 CSV；超大规模导出的流式传输不在本轮范围内。普通日期模式和复盘页继续使用已有的日聚合接口。

## 本机验证

2026-09-26，使用同一份本地数据库副本的 80,995 条事件，范围为 2026-04-01 至 2026-09-27，交替比较完整事件分页读取与聚合读取，共 3 轮。比较包含 HTTP 响应读取与 JSON 解析，不包含浏览器绘图；两种路径均未启用响应压缩。

| 指标 | 完整事件分页 | 聚合统计 |
| --- | ---: | ---: |
| HTTP 请求 | 41 | 1 |
| 响应体积 | 62,165,147 字节 | 1,359,983 字节 |
| 本机耗时中位数 | 454 ms | 483 ms |

本轮主要减少约 97.8% 的传输体积和浏览器中的事件对象数量；不将其描述为数据库查询耗时下降。数据库仍需扫描所选范围内的事件完成聚合。Token 各分项、已存费用、缓存节省估算逐项比对一致（浮点容差 `1e-7`）；浏览器验证了精确日期筛选、对比周期、详情上一页/下一页和完整统计保持不变。

自动测试覆盖超出第一页的 2,505 条事件、边界和空范围、对比周期、项目及多维度筛选、游标隔离、每事件缓存节省截断、HTTP 鉴权；PostgreSQL/MySQL 的聚合和分页由 CI 的真实数据库服务验证。
